# EY-AY Chatbot

Pokemon Q&A chatbot. An intent classifier (sentence embeddings + PyTorch) works out what is
being asked, answers come from PokeAPI data and Markdown guides (RAG), and an optional free
LLM (Groq / OpenRouter) handles open-ended questions. Everything runs locally for free.

## Project Structure
```

│   ├── main.py               # Routes and service wiring
│   ├── chatbot_service.py    # Answer pipeline (see "How a message is answered")
│   ├── dex_api.py            # Pokedex browser: /dex/search, /dex/pokemon|move|item/{slug}
│   ├── llm_fallback.py       # Groq / OpenRouter client
│   └── models.py             # Pydantic request/response schemas
├── chatbot/

│   ├── embedder.py           # Local sentence-transformers model (bge-small)
│   ├── intent_classifier.py  # PyTorch MLP head
│   ├── train.py              # Trains the classifier, reports held-out accuracy
│   ├── pokedex.py            # Pokedex data, name detection, masking, type chart, evolutions
│   ├── answers.py            # Data-backed answer per intent
│   ├── retriever.py          # RAG: passages, vector index, semantic search
│   └── data/
```

## Commands (run from project root unless noted)
- Install: `python -m venv venv && venv/Scripts/pip install -r requirements.txt`
- Set up DB (creates tables, syncs intents + replies from JSON): `python scripts/migrate_json_to_db.py`
- Refresh Pokemon data (optional, data is committed): `python scripts/import_pokeapi.py`
- Train classifier (after editing intents.json): `python chatbot/train.py`
- Build RAG index (optional, also built on first backend start): `python scripts/build_rag_index.py`
- Backend: `uvicorn backend.main:app --port 8000 --reload`
- Frontend: `cd frontend && npm run dev` (talks to `VITE_API_URL`, default http://localhost:8000)
- Tests: `python -m pytest`
- Lint: `flake8 backend chatbot shared scripts tests`

The embedding model (~130 MB) downloads from Hugging Face on first use, then works offline.

## How a message is answered (backend/chatbot_service.py)
1. Classify intent; detect Pokemon/move/item/type/region names (typo-tolerant)
2. Small talk (greeting, thanks, out_of_scope...) -> stored reply from MySQL
3. Data answer from the Pokedex (answers.py); follow-ups reuse names from earlier turns
4. LLM, if a key is set, grounded with Pokedex facts + retrieved passages
5. Without an LLM: best matching guide section (RAG), then data for opinion questions
6. Otherwise describe the mentioned name, then the stored clarifying reply, then a default

## Notes
- Confidence threshold: 0.5 (`CONFIDENCE_THRESHOLD`); chosen from the held-out eval (90% coverage, 98% precision)
- After editing intents.json: retrain, check held-out accuracy in the output, re-run the migration
- After editing knowledge/*.md or re-importing the Pokedex: the RAG index rebuilds automatically
- Pokedex covers default forms plus regional forms (own learnsets) and Mega/Primal forms (with their stone or orb). Learnsets come from the newest game with data
- Pokedex page: clean light tables; Gengar purple theme is only for the chat widget
- Sprites load from PokeAPI's sprite repo on GitHub (animated Black/White up to #649, static after; shiny via the star button). A missing sprite shows a silhouette of the closest one we have
- LLM fallback is disabled unless `GROQ_API_KEY` or `OPENROUTER_API_KEY` is set (both have free tiers)
